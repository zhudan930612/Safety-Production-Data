# 沈阳事故分析平台项目说明（AI协作版）

## 1. 文档定位
本说明用于指导 AI 在“沈阳事故分析平台”中的文档编写、方案设计与需求拆解。
目标是确保 AI 输出可执行、可追溯、可评审。

## 2. 项目一句话定义
沈阳事故分析平台是面向监管部门与企业的事故数据汇聚与分析平台，支持事故上报、调查复盘、风险识别、趋势分析与监管决策。

## 3. 产品目标
1. 建立统一事故数据底座，打通多来源事故信息。
2. 提供标准化事故分级、分类、归因与复盘能力。
3. 支持区域、行业、企业多维分析与预警。
4. 支撑监管部门形成数据驱动的治理闭环。

## 4. 核心场景
1. 企业或属地上报事故与事件信息。
2. 监管人员审核、补正、归档事故记录。
3. 分析人员进行事故归因、规律识别、风险研判。
4. 管理层查看看板、预警和专题分析报告。

## 5. 角色与权限模型
1. 平台超级管理员：全局配置、字典管理、权限治理。
2. 监管管理员：事故审核、统计分析、报表导出。
3. 行业/区域管理员：本辖区数据管理与分析。
4. 企业用户：事故填报、整改反馈、材料上传。
5. 分析人员：专题分析、模型配置、结论输出。

## 6. 业务范围
### 6.1 In Scope
1. 事故信息采集与标准化。
2. 事故审核、退回补正、归档管理。
3. 事故分类分级、原因标签与责任维度。
4. 趋势分析、对比分析、热力分布、专题报表。
5. 风险预警规则配置与预警推送。
6. 数据导出与审计日志。

### 6.2 Out of Scope
1. 与事故分析无关的通用办公流程替代。
2. 未立项的复杂预测模型生产化落地。
3. 线下调查执法系统的完整替代。

## 7. 关键能力清单
1. 事故台账：统一记录事故全过程信息。
2. 归因体系：支持多标签、多层级原因树。
3. 分析引擎：时间、区域、行业、企业多维钻取。
4. 预警引擎：阈值预警、同比异常预警、聚集性预警。
5. 报表中心：监管口径报表与专题分析报告。
6. 审计追踪：关键操作与口径变更全留痕。

## 8. 非功能要求
1. 可用性：关键监管期稳定可用。
2. 性能：支持高频查询与大屏展示。
3. 安全：敏感信息脱敏、权限隔离、访问审计。
4. 可观测：日志、告警、链路可追踪。
5. 可扩展：标签体系、分析维度、报表模板可扩展。

## 9. 数据与指标口径
1. 事故上报及时率 = 按时上报事故数 / 应上报事故数。
2. 审核通过率 = 审核通过记录数 / 审核总记录数。
3. 事故复发率 = 同类事故重复发生数 / 事故总数。
4. 整改闭环率 = 已闭环整改数 / 应整改数。
5. 高风险预警命中率 = 命中高风险事件数 / 预警总数。

## 10. AI 执行约束
1. 未确认口径不得写成正式统计指标。
2. 涉及事故分级标准必须标注来源依据。
3. 涉及结论性表述必须区分“事实”与“推断”。
4. 变更指标定义时必须同步更新相关报表文档。

## 11. AI 标准执行流程
1. 读取本说明与相关目录文档。
2. 提取已确认事实、待确认项、假设项。
3. 生成目标文档（FD、PRD、评审稿等）。
4. 执行一致性校验（术语、指标、版本）。
5. 输出变更摘要与待确认清单。

## 12. 输出格式要求
1. 修改文件列表。
2. 核心变更点（每文件1-3条）。
3. 新增待确认项。
4. 风险与建议。
